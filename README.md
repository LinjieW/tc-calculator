# 薪酬测算

加班与总薪酬计算器，外加一个税后到手的板块。零依赖、零网络请求、无构建步骤。

**→ https://linjiew.github.io/tc-calculator/**

手机浏览器打开就能用。同一个 `index.html` 也可以直接发给别人双击打开。

```bash
open index.html      # 本地打开
./build.sh --run     # 顺带构建一个 macOS App（ad-hoc 签名，本机自用）
```

`./build.sh` 一次产出 `薪酬测算.app` 和根目录的 `index.html`（`web/` 折成的单文件），
同源同构建；CI 会检查这两者没有跑偏。

## 仓库里的数字是通用的

预填值是一组整数示例，不是任何人的实际待遇：基本工资 100,000、年终奖 4,000、
401(k) 匹配 5%、利润分享 2%、通讯补贴 1,200、PTO 80 小时。
自己用的时候在「假设」面板输一次真实数字——存在浏览器 localStorage 里，不会离开设备。

## 模型

每条公式都对应原工作簿 Backup 表的一个单元格（`web/app.js` 里逐行标了）：

| 项目 | 公式 | 单元格 |
| --- | --- | --- |
| 标准时薪 | 基本工资 ÷ 标准年工时 | `B16` |
| 加班时薪 | 标准时薪 × 加班倍率 | `B17` |
| 加班费 | 加班小时 × 加班时薪 | `B22` |
| 变动薪酬 | 加班费 + 年终奖 | `C22` |
| 等效年终奖 % | 变动薪酬 ÷ 基本工资 | `D22` |
| 总现金薪酬 | 基本工资 + 变动薪酬 | `E22` |
| 401(k) 匹配 | 匹配% × (基本工资 + 加班费) | `F22` |
| 利润分享 | 基本工资 × 利润分享% | `B18` |
| 总薪酬包 | 总现金 + 匹配 + 利润分享 + 通讯补贴 | `I22` |
| 反查 | `ROUND(MAX(0,(目标% × 基本工资 − 年终奖) ÷ 加班时薪), 0)` | `B52` |

填回工作簿那组假设时，明细表 26 行 × 8 列与反查 9 行逐格一致。

**显示值会互相对齐**：页面上的数字先按当前精度取整再相加，所以读者能对上的每条等式
（总薪酬包 = 总现金 + 匹配 + 利润分享 + 通讯补贴）在屏幕上都严格成立。
代价是标题偶尔比「真实值直接取整」差 1 美元。导出 CSV 走未取整的精确值。

## 税后到手

单身申报、只用标准扣除的**估算，不是报税结论**。预填 2026 年的数字，
档位表和所有参数都可以直接编辑（最高一档「上限」留空表示以上全部）：

| 参数 | 来源 |
| --- | --- |
| 联邦档位 + 标准扣除 16,100 | IRS Rev. Proc. 2025-32 |
| DC 档位 4%–10.75% | DC OTR（2022 年起未变） |
| 社保上限 184,500 | SSA 2026 |
| 401(k) / HSA / IRA 上限 24,500 / 4,400 / 7,500 | IRS 2026 |
| OBBBA 加班扣除 上限 12,500，MAGI 150,000 起退坡 | OBBBA，2025–2028 |

三个容易算错的地方：

- **401(k) 不减 FICA，HSA 走工资扣除才减**——所以 HSA 旁边那个勾选框不是装饰。
- **OBBBA 加班免税只免「溢价」**——1.5 倍里只有多出来的 0.5 倍算 qualified overtime
  （加班费的 ⅓），只作用于联邦所得税，DC 不跟随。
- **边际税率是实测的**——工资加 1,000 重算一遍再除，所以自动含进 FICA、社保上限
  和加班扣除退坡，也会体现跨档。

传统 IRA 在有公司退休计划且收入较高时通常不可抵扣，页面会提示但不替你判断。

## PTO

**PTO 不改变任何金额**——它本来就含在基本工资里，所以基本工资、加班费、总薪酬包、
401(k) 匹配和全部税额，加不加 PTO 都一样。加班时薪仍按 `基本工资 ÷ 标准年工时` 算
（除数是「工资覆盖的小时数」，PTO 不缩小它）。

它改变的是两件事：**实际每工作一小时值多少**，以及**加班要挤进多少周**——
80 小时 PTO 意味着 50 个工作周，同样 250 小时加班从每周 4.8 变成 5.0 小时。
环形图里 PTO 单独占一块，是**从基本工资里切出来的**，两块加起来才是全额。

## 目录

```
index.html            生成物：web/ 折成的单文件，也是 GitHub Pages 的入口
web/                  源码（index.html / app.css / app.js + 三个 UI kit 文件）
src/main.swift        macOS 宿主：窗口、菜单、保存文件、打印、主题同步
build.sh              编译 + 组装 .app + ad-hoc 签名 + 打包单文件
tools/                验收与构建工具（见下）
```

界面用的是 apple-ui-kit。`web/` 下的 `tokens.css` / `components.css` / `ui.js` /
`motion.js` / `select-menu.js` 是它的拷贝，**只有一处本地改动**：`tokens.css` 里
`--accent-1/2/3` 重新取了值（只改值不改名字），因为环形图需要六个色相而 kit 出厂只有三个。
文件里有注释标出。

## 验收

`tools/checks.js` 在**真 WKWebView** 里驱动页面（`tools/wkcheck.swift`）。
不用浏览器是有原因的：UI kit 自己的错题本第一条就是「在 Chrome 里正常、只在 WebKit 里坏」。

```bash
swiftc -O tools/wkcheck.swift -o /tmp/wkcheck
/tmp/wkcheck "$PWD/web/index.html" "$PWD/tools/checks.js" 1100 900
/tmp/wkcheck "$PWD/index.html"     "$PWD/tools/checks.js" 390 840
```

`web/` 和 `index.html` 在两个尺寸下都必须 0 failure。它检查模型数值、显示值加不加得起来、
SVG 有没有被压成 0×0、切主题会不会丢滚动/输入/焦点、窄屏有没有横向溢出、
键盘能不能走到、税表开关和档位编辑算得对不对。

`E` 块里的预期常量是照公式**独立算出来**的。改了默认值就得重算——
别去读 app 自己的输出，那样这套验收就变成「app 输出什么就认什么」。

## 两点说明

**iOS 的文件预览打不开它**，这不是页面的问题：Quick Look 只渲染 HTML 和 CSS、
不执行 JavaScript，而这页所有数字都是打开时算的。用上面那个网址即可。
页面里有段 `<noscript>` 会在脚本没运行时解释这件事。

**签名**是 ad-hoc（本机没有代码签名证书）。本机编译、没有 quarantine 标记，
Gatekeeper 不拦。想换真证书就把 `build.sh` 里的 `--sign -` 换掉。
